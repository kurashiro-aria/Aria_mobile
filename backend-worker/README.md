# ARIA Cloud Gateway

Cloudflare Worker compatible gateway for the existing Android contract. It keeps the Python backend available for VPS/self-hosted deployments and does not move ARIA memory to the cloud.

## Local checks

```bash
npm test
npx wrangler dev
```

Set local secrets in `.dev.vars` (never commit it):

```text
ARIA_LLM_API_KEY=...
ARIA_CLOUD_CLIENT_TOKEN=...
```

## Deploy

```bash
npx wrangler login
npx wrangler secret put ARIA_LLM_API_KEY
npx wrangler secret put ARIA_CLOUD_CLIENT_TOKEN
npx wrangler deploy
```

The first deployment uses the `workers.dev` hostname generated by Wrangler. No URL is stored in this repository. Configure `ARIA_CLOUD_ENDPOINT` in the Android build only after a real HTTPS URL exists.

The Worker accepts `POST /v1/brain/respond` and `GET /health`, preserves `requestId`, validates JSON and content size, rejects duplicates, applies best-effort per-isolate rate limiting, and calls Gemini `generateContent`. Production logs do not include prompts, memories, API keys, or client tokens. The client token is a prototype quota barrier because anything shipped inside an APK can be extracted; stronger device authentication can be added later.

Streaming is intentionally not enabled in V1. The existing Android `BrainResponse` contract is non-streaming, and adding streaming would require a coordinated client protocol change.

Cloudflare Workers Free limits and Gemini quota vary by account and date; verify current limits in the provider dashboards before relying on production traffic.
